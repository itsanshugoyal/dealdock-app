# Go-live checklist, 7 November 2026

What has to happen before the first paying creators, in order, with who does it. Meta's App Review is in progress and can finish later: until it does, only Instagram accounts with a role on the app can be used. Sources for every figure are in the research notes from 7 November; vendor prices and timelines change, so check them on each vendor's dashboard.

## Recommended setup

| Area | Choice | Why |
|---|---|---|
| Web app | Vercel Pro at `app.dealdock.io`, functions in `sin1` (Singapore) | Vercel's free plan is non-commercial only. Its default region is Washington, so pin Singapore, next to the API. |
| API and worker | Railway Pro in Singapore, API at `api.dealdock.io` | Railway has no India region; Singapore is the closest. |
| Database | Railway Postgres in Singapore, with point-in-time restore on, plus a nightly copy stored off Railway | It sits on the same private network as the API and worker, keeps restores for about 4 weeks on Pro, and needs no connection pooler because the API and worker run continuously. This replaces the earlier Neon plan in [the deployment handoff](deployment-preflight.md). Neon (Singapore, 7-day restore) is the alternative. Supabase is the only one with a Mumbai region, but restore-to-any-moment costs $100 a month extra there. |
| Queues | Railway Redis in Singapore, with AOF persistence on | BullMQ talks to Redis constantly, so per-command billing (Upstash) climbs. |
| Billing | Razorpay for INR at launch. Apply to Paddle now for buyers outside India; Dodo Payments if Paddle declines. | See [international payments](#can-razorpay-take-international-payments). |
| Errors and uptime | Sentry free plan on web, API and worker; UptimeRobot free plan | Both free plans allow commercial use. |
| Data location | Singapore is allowed | India's DPDP Act does not require local storage. Its transfer restrictions apply only to countries the government blacklists, none are listed, and that section starts 13 May 2027. Name the location in the privacy policy. |

## You: accounts and settings

Do these roughly in this order; several later steps depend on step 1.

1. **Publish the policy pages on dealdock.io.** Razorpay's live mode, Paddle's domain review, Google's Gmail verification and Meta's App Review all check them. Each must be linked from the site's navigation or footer:
   - Terms of service, with the legal company name;
   - Privacy policy. It must name every service that handles creator data: OpenAI and Groq (AI), Google (Gmail), Meta (Instagram), Razorpay and Paddle, Clerk, Railway and Vercel. It must say data is stored in Singapore, and that Gmail data is never used to train AI models;
   - Refund and cancellation policy;
   - Shipping or delivery policy ("a digital service, delivered online");
   - Contact page;
   - a pricing page and a features page, which Paddle requires.
2. **Add DNS records** for `dealdock.io`. Copy exact values from each dashboard.

   | Host | Type | Points to |
   |---|---|---|
   | `app` | CNAME | the target Vercel shows for the project |
   | `api` | CNAME and TXT | the `…up.railway.app` target and the verification TXT Railway shows. Without the TXT, Railway returns 404. |
   | `clerk`, `accounts` | CNAME | `frontend-api.clerk.services` and `accounts.clerk.services` |
   | `clkmail`, `clk._domainkey`, `clk2._domainkey` (and `clkmail2` if listed) | CNAME | the values Clerk's production instance shows |
   | `@` | TXT | `google-site-verification=…`, from Search Console. Gmail verification needs it. |
   | `_dmarc` | TXT | `v=DMARC1; p=none; rua=mailto:<your inbox>` |

   Keep the existing Zoho MX, SPF and DKIM records, and keep exactly one `v=spf1` record. Don't change the marketing site's root records. If the DNS is on Cloudflare, Clerk's records must be "DNS only". Records can take up to 72 hours to work.
3. **Clerk production:**
   - Set the production domain to `dealdock.io` and add `app.dealdock.io` as an allowed subdomain.
   - Check that the DNS records verify.
   - Set up Google sign-in with its own OAuth client.
   - The API already reads the session token from the `Authorization` header and allows only the app's origin. Since 7 November it also rejects tokens issued to any other origin in production.
4. **Hosting:**
   - **Vercel project:** root `apps/web`, region `sin1`.
   - **Railway project:** four services in Singapore: API, worker, Postgres and Redis.
   - **Doppler:** sync `prd_web` to Vercel, `prd_api` to the API service and `prd_worker` to the worker.
   - **Database:** turn on Railway's point-in-time restore, and Redis AOF.
5. **Production values in Doppler** (in addition to the keys you already have):
   - **Origins:**
     - `WEB_APP_URL=https://app.dealdock.io`
     - `NEXT_PUBLIC_API_URL=https://api.dealdock.io`
     - `PUBLIC_API_URL=https://api.dealdock.io`
   - **Callbacks:**
     - `IG_OAUTH_REDIRECT_URI=https://api.dealdock.io/ig/callback`
     - `GOOGLE_REDIRECT_URI=https://api.dealdock.io/email/callback`
   - **AI:** `AI_PROVIDER=openai`, `AI_FALLBACK_PROVIDER=groq`, both keys, and `OPENAI_REASONING_EFFORT=high`.
   - **Secrets:**
     - `TOKEN_ENCRYPTION_KEY` and `MEDIA_SIGNING_KEY`, generated once and API only.
     - VAPID keys: the public key on the web app, the key pair on the worker.
   - **Stay off until Meta approves:** `META_COMMENTS_ENABLED`, `META_INSIGHTS_ENABLED` and `META_HUMAN_AGENT_ENABLED`.
6. **Razorpay:**
   1. In test mode, create the Solo, Studio and Roster plans and add the webhook `https://api.dealdock.io/webhooks/razorpay` with a secret.
   2. Run one full subscription cycle: subscribe, renew, fail, cancel.
   3. After live approval, repeat the plans and the webhook in live mode.
   4. Leave international cards off for subscriptions at launch.
7. **Paddle:** apply now; it needs the pages from step 1.
   - **Domains:** submit both `dealdock.io` and `app.dealdock.io`. Manual review takes about 5–7 business days.
   - **Wording:** describe DealDock as "a deal inbox and CRM for creators, with replies you approve". Never use "DM automation" or "social media automation". Paddle's acceptable-use policy bans automated social media marketing and messaging-app marketing tools, and it decides what falls under that. The marketing-site prompt already rules out implying automatic replies; keep it that way.
   - **Costs:** fees are 5% + 50¢ per sale. Payouts are monthly, by wire or Payoneer, and a wire to an Indian bank likely costs $15.
8. **Gmail.**
   - **Setup:**
     - **Google Cloud project:** create one for the Gmail integration, with a Web OAuth client whose redirect is `https://api.dealdock.io/email/callback`, and a consent screen.
     - **Domain:** verify `dealdock.io` in Search Console.
     - **Pub/Sub:** create a topic that `gmail-api-push@system.gserviceaccount.com` can publish to, with a push subscription to `https://api.dealdock.io/webhooks/gmail?token=<GMAIL_PUBSUB_VERIFICATION_TOKEN>`.
     - **Publishing status:** set it to **In production** (unverified). That allows up to 100 users, who see a warning screen.
     - **Avoid Testing mode:** access expires every 7 days there, so creators would have to reconnect weekly.
   - **Start verification now.** It takes 4–8 weeks in total:
     - brand verification, which takes 2–3 days;
     - a demo video and a reason for each scope;
     - a CASA security assessment from an approved lab: about $500–900 a year for the basic level, with the letter in 2–3 weeks. It is renewed yearly.

   `gmail.readonly` is what triggers the assessment.
   - **Fallback if verification stalls:** creators forward brand mail to a DealDock address, and DealDock uses only `gmail.send`, which needs no assessment. Replies the creator sends from Gmail itself would then be missed. This needs engineering work.
9. **Monitoring and accounts:**
   - Create Sentry projects for web, API and worker, and add their keys to Doppler.
   - In UptimeRobot, monitor `https://app.dealdock.io` and `https://api.dealdock.io/ready`.
   - Turn on two-factor login on the registrar and every vendor account, and domain auto-renew.
10. **Reviews only you can do:**
    - the blind 50-draft review of GPT-6 Luna drafts;
    - a chartered accountant's review of invoice fields, TDS and the purpose code;
    - legal review of the privacy policy and the spoken AI disclosure.

## Can Razorpay take international payments?

Yes, but it is the wrong tool for foreign subscriptions at launch.

- **What it can do:** take international cards and settle in INR. Subscriptions on international cards are available to eligible accounts, after Razorpay's banking partners approve, which takes 2–3 business days with the policy pages live.
- **Fees:** up to 3% for international cards, plus 18% GST on the fee and 0.9% for subscriptions on cards.
- **You stay the seller.** Razorpay is not a merchant of record, so foreign VAT and sales tax are yours to register for and pay. Its own merchant-of-record product is waitlist-only.
- **Chargebacks are yours too.** Foreign cardholders have up to 120 days to dispute, and network arbitration fees (Visa: USD 600) are passed on.
- **Recommendation:** Razorpay for INR. Paddle collects and pays the tax for buyers abroad. The fallbacks are Dodo Payments (4% + 40¢, +1.5% international, +0.5% subscriptions) or Polar, which pays Indian sellers through Stripe Connect. Stripe itself is still invite-only in India, and Lemon Squeezy is moving into Stripe's waitlisted Managed Payments.

## WhatsApp: scopes, steps, effort and blockers

**Permissions:** `whatsapp_business_messaging` and `whatsapp_business_management`, with Advanced Access ([Meta, Tech Providers](https://developers.facebook.com/docs/whatsapp/solution-providers/get-started-for-tech-providers)). Embedded Signup may also ask for `business_management`; confirm it in the app dashboard.

**Steps:**
1. **Meta Business Verification:** up to 14 business days. Instagram's Advanced Access needs it too, so start it now.
2. **Register as a Tech Provider:** add the WhatsApp product to the Meta app, then pass App Review with two screen recordings, one sending a message and one creating a template.
3. **Configure Embedded Signup:** version 4, since versions 2 and 3 are deprecated from 15 October 2026. Turn on coexistence, so creators keep their number and the WhatsApp Business app.
4. **Build:** a WhatsApp channel behind the same channel structure as email:
   - connect through Embedded Signup;
   - receive messages, delivery statuses and the history import;
   - send replies after approval, within the 24-hour window;
   - offer approved templates for follow-ups after the window.
5. **Test:** on a real number, then submit the review.

**Effort:** about 3–5 weeks of building, alongside 2–4 weeks of Meta approvals.

**What works in DealDock's favour:**
- **The same number:** creators can keep their number and the WhatsApp Business app ("coexistence", supported in India). Messages are mirrored to DealDock.
- **History:** up to 6 months of one-to-one chats can be imported, with media from the last 14 days, if the import finishes within 24 hours of connecting.
- **Messages sent from the app:** what the creator sends from the WhatsApp Business app stays free.

**Blockers and costs:**
- **Reply window:** free-form replies only within 24 hours of the customer's last message. After that, only Meta-approved templates, charged per message: about ₹0.86 for marketing and ₹0.12 for utility, from third-party figures.
- **Free allowance:** from 1 October 2026, each number gets 1,000 free service messages a month.
- **Billing:** Indian accounts must be billed in INR by 31 December 2026, and each creator adds their own payment card to Meta.
- **Coexistence limits:** group chats don't sync, some app features switch off, and the link drops if the phone is inactive for about 14 days.
- **Personal WhatsApp:** creators on personal WhatsApp must switch to the Business app first.
- **AI rules:** since 15 January 2026, Meta bans general-purpose AI assistants on WhatsApp. AI that serves a business task is allowed. DealDock drafts replies that a person approves, which reads as allowed, but confirm it during review.

**Recommendation:** start Meta Business Verification now. Build WhatsApp after launch, around coexistence.

## TikTok: scopes, steps, effort and blockers (creators outside India)

TikTok is banned in India. This section covers creators elsewhere. TikTok's sites are also blocked on Indian networks, including the one used for this research, so building and testing from India needs a VPN or a machine abroad. Production servers in Singapore are not affected.

**Which TikTok platform.** DMs and comments come only through the **TikTok API for Business** (business-api.tiktok.com), using its "TikTok Accounts" permission plus separate access to the Business Messaging API. TikTok's general developer platform (Login Kit, Display and Content Posting APIs) has no comment or messaging scopes: only profile, video-list, posting and data-export scopes ([scopes reference](https://developers.tiktok.com/docs/en/tiktok-api-scopes)).

**Scopes DealDock would request:**

| DealDock feature | Scopes | Notes |
|---|---|---|
| Connect a creator | `user.info.basic`, `user.info.username`, `user.info.stats` | Identity, handle and follower counts. |
| DMs | `message.list.read`, `message.list.send`, `message.list.manage` | `message.list.manage` appears in TikTok's own token example ([Accounts API authentication](https://business-api.tiktok.com/portal/docs/accounts-api-authentication/v1.3)). The read and send names come from integrators' live sign-in requests ([ChatbotX](https://github.com/ChatbotXIO/ChatbotX/pull/1231)). New DMs arrive through the `DIRECT_MESSAGE` webhook ([webhook configuration](https://business-api.tiktok.com/portal/docs/get-a-business-messaging-webhook-configuration/v1.3)). |
| Comment leads | `video.list`, `comment.list`, `comment.list.manage` | Comments arrive through the `COMMENT` webhook, and replies post through `/business/comment/reply/create/`. An integrator's app was approved with exactly these scopes plus `user.info.basic` ([ChatbotX](https://github.com/ChatbotXIO/ChatbotX/pull/1572), [OpenReply](https://github.com/diwenne/openreply/pull/75)). TikTok's own comment-to-message feature, like Instagram's private replies, is part of Business Messaging and region-restricted. |
| Proof of results | `video.insights`, `user.insights` | Post and account numbers, for the proof-of-results feature. |
| Not needed now | `video.upload`, `video.publish`, `biz.spark.auth`, `tcm.order.update` | `biz.spark.auth` covers Spark Ads (TikTok's partnership ads) and could later track that add-on. `tcm.order.update` belongs to TikTok's creator marketplace orders. |

Request only scopes the demo video shows in use. Unused scopes are a common rejection reason ([bundle.social](https://bundle.social/blog/tiktok-api-approval)).

**Steps:**
1. **Developer app:** create a TikTok for Business developer account and an app at business-api.tiktok.com/portal/apps, add the "TikTok Accounts" permission (business user, media and comments), and fill in the Accounts API access form, which an integrator reports has been required since March 2026.
2. **Business Messaging access:** apply for it separately. It needs TikTok's data-security and privacy review, plus TikTok's US data-security review to serve US accounts ([access requirements](https://business-api.tiktok.com/portal/docs/access-to-business-messaging-api/v1.3)).
3. **Build:** a TikTok channel behind the same channel structure as email:
   - sign-in with tokens stored encrypted, on the API only;
   - signature-checked webhooks for DMs and comments;
   - conversation and message sync;
   - replies sent after approval, under TikTok's limit of 10 messages within 48 hours of the person's last message;
   - comment leads on TikTok, results for proof of results, and "Connect TikTok" in Settings.
4. **Test:** on real Business accounts in supported regions, then record the review video and submit.

**Effort:** about 3–4 weeks of building. DMs take about two weeks on the existing channel structure, comment leads about one week reusing the Instagram feature, and results a few days. TikTok's reviews come on top: the Accounts API review is reportedly days to a few weeks, and the Business Messaging data-security review has no published timeline.

**Blockers:**
- **Business accounts only.** Personal accounts can't connect. Switching to a Business account removes TikTok's full sound library and its creator monetization programs, a real cost for many creators ([Hootsuite](https://blog.hootsuite.com/tiktok-business-vs-personal/), [Soundstripe](https://www.soundstripe.com/blogs/tiktok-music-library-explained)). Comment leads and results need the same Business account.
- **Regions.** DMs through the API are unavailable for accounts registered in the EEA, Switzerland and the UK; comments still work there ([ChatbotX](https://github.com/ChatbotXIO/ChatbotX/issues/1563)). The Business Messaging API is an open beta.
- **Message limits.** The business can't start conversations, can send at most 10 messages within 48 hours of the customer's last message, and can't send video or voice. Media sending is unavailable in the US, the UK and the EU. The account must accept DMs from everyone.
- **Reviews.** The Accounts API form and app review, the Business Messaging data-security review, and the US review for US accounts.
- **Unverified details.** The webhook signature (an integrator reports a `TikTok-Signature` header signed with the app secret), token lifetimes and some payload fields need checking on a live account.

**Recommendation:** for creators outside India, start with comment leads and results. They need only the Accounts API, work in more regions, and reuse the Instagram features. Add DMs once Business Messaging access is granted.
